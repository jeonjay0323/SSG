# AI 저작물 저작권 검토

> 프로젝트를 진행하며 저작권·권리 문제가 걸릴 지점을 미리 모아둔다.
> **법률 자문이 아니다.** 확인이 필요한 질문의 목록이다.

---

## 1. 왜 필요한가

이 프로젝트는 세 겹으로 권리가 얽힌다.

```
원작(웹소설)  →  AI 생성 영상  →  여럿의 기여가 섞인 결과물
```

각 단계마다 **누구의 것인가**가 달라지고, 마지막 단계는
참여자가 이미 물어본 문제다 — *"다 만들어진 영상은 어디로 가는 거냐"*,
*"공유할 수 있냐"*.

---

## 2. 전제 — AI 창작물은 현행법상 저작물이 아니다

한국 저작권법 제2조 1항은 저작물을 **"인간의 사상 또는 감정을 표현한 창작물"** 로 정의한다.
AI가 만든 결과물은 인간의 사상·감정 표현이 아니므로 **이 정의에 들어가지 않는다.**

| | |
|---|---|
| 한국 | AI 창작물에 저작권을 부여하지 않는다 |
| 미국 · 유럽 · 일본 | 마찬가지로 보호 대상에서 제외 |
| AI 회사 · 개발자 · 사용자 | 어느 쪽에도 저작권을 인정하지 않는다 |

> 근거: 최다혜 외 (2023), [JCCT 9(1), 777-786](https://doi.org/10.17703/JCCT.2023.9.1.777)

**즉 멀티툴이 만든 영상은 현재 아무의 저작물도 아닐 가능성이 크다.**
이것이 이 문서의 모든 질문이 출발하는 지점이다.

---

## 3. 이 프로젝트에서 실제로 걸리는 지점

### 3.1 참여자가 쓴 문장

| 질문 | 현재 상태 |
|---|---|
| 40자 문장에 저작물성이 있는가 | 짧은 문구는 창작성 요건을 충족하기 어렵다는 것이 일반적 견해 |
| 있다면 누구 것인가 | 쓴 사람 |
| 서비스가 그것을 쓸 근거는 | **없다.** 이용약관도 동의 절차도 없다 |
| 탈락한 문장은 | 서버 메모리에만 있다가 사라진다 |

**미확인:** 문장이 저작물이 아니더라도, 참여자가 "내 것"이라 느낀다면
법과 별개로 **경험 설계의 문제**가 된다.

### 3.2 생성된 영상

2장에 따르면 저작물이 아니다. 그러면 이런 질문이 남는다.

| 질문 |
|---|
| 저작물이 아니라면 누구나 가져다 쓸 수 있는가 |
| 참여자가 "내가 만들었다" 고 말할 근거는 무엇인가 |
| 서비스가 이를 홍보에 쓰려면 별도 동의가 필요한가 |

### 3.3 완성된 이야기 — 여럿의 기여가 섞인 결과물

6씬이 각각 다른 사람의 문장에서 나온다.

| 유형 | 성립 조건 |
|---|---|
| **공동저작물** | 각자의 기여를 분리해 이용할 수 없을 때 |
| **결합저작물** | 각 부분을 따로 떼어 쓸 수 있을 때 |

멀티툴의 이야기는 **장면 단위로 분리 가능**하므로 결합저작물에 가까워 보인다.
다만 각 장면이 AI 생성물이라 애초에 저작물이 아닐 수 있어, 이 분류 자체가
적용되지 않을 여지도 있다.

**이것이 연구 질문과 직결된다.** 참여자가 완성본을
*"내 것"* 이라 부르는지 *"우리 것"* 이라 부르는지가
[비교 인터뷰](../Research/비교%20인터뷰%20가이드.md) 22번 문항이다.
**법적 구분과 체감이 어긋나는 지점**이 그대로 연구 소재가 된다.

### 3.4 원작 웹소설 — 솔로툴의 경우

작가가 자기 원고를 넣어 영상을 만드는 구조다.

| 질문 | 상태 |
|---|---|
| 작가 본인 작품이면 문제 없는가 | 대체로 그렇다 |
| **CP사와 계약한 작품이라면** | **2차적저작물작성권이 CP사에 있을 수 있다** |
| 그 경우 작가가 임의로 영상화할 수 있는가 | **미확인** |

[작가 인터뷰 §4](../Research/작가%20인터뷰.md)에서 미확인으로 남겨둔 항목이다.
**서비스화한다면 가장 먼저 확인해야 한다.** 작가가 쓸 수 없는 서비스가 된다.

### 3.5 학습 데이터

| 사용 모델 | 용도 |
|---|---|
| Veo 3.1 | 영상 생성 |
| gemini-2.5-flash-image | 프레임 리스테이징 |
| gemini-2.5-flash | 문장 해석 |

무엇을 학습했는지 알 수 없다(블랙박스). 선행 연구에서 사용자들이
**학습 데이터의 적법성**과 **AI가 저작권을 인지하고 창작하는지**를 우려 항목으로 꼽았다.

우리가 통제할 수 없는 영역이지만, **사용자가 물어볼 수 있는 질문**이므로
답할 말은 준비해야 한다.

### 3.6 스타일 레퍼런스 — 기존 작품을 명시하고 있다

`Config/worlds/*.json` 의 `toneRef` 가 **실존 저작물을 지목한다.**

| 세계 | toneRef |
|---|---|
| 현대 헌터물 · 웹툰 | 〈나 혼자만 레벨업〉 |
| 이세계 용사 · 애니메이션 | 〈전생했더니 슬라임이었던 건에 대하여〉 |
| 야근 사무실 괴담 | 드라마 〈미생〉 |

| 질문 |
|---|
| 작품명을 프롬프트에 넣어 화풍을 유도하는 것이 문제가 되는가 |
| 화풍·분위기는 아이디어 영역이라 보호 대상이 아니라는 견해가 일반적이나, **특정 작품을 지목하는 것**은 다른 문제일 수 있다 |
| 공개 서비스로 낼 때도 이 표기를 유지할 것인가 |

**대안:** 작품명 대신 화풍의 속성을 서술로 풀어 쓴다.
(예: 〈나 혼자만 레벨업〉 → "고대비 흑백 톤, 굵은 외곽선의 한국 웹툰 화풍")

### 3.7 배우 레퍼런스 이미지

확인한 결과 **텍스트 프롬프트로 생성된 이미지**다.

| | |
|---|---|
| 생성 방식 | `Tools/build_world.py` 가 `character` 서술로 생성 |
| 실존 인물 지칭 | 없음 — "20대 후반 한국 남성" 식의 일반 서술 |
| 초상권 | 특정인을 지목하지 않았으므로 직접적 문제는 없어 보인다 |
| 다만 | 생성 결과가 **우연히 실존 인물과 닮을** 가능성은 통제할 수 없다 |

솔로툴의 캐릭터 이미지에는 **생성 도구의 워터마크가 찍혀 있다.**
AI 생성물임을 드러내는 표시이므로, 지우지 않는 편이 안전하다.

## 4. 지금 당장 답해야 할 질문

결과물을 공유·저장하는 기능을 붙이려면 아래가 먼저 정해져야 한다.
참여자가 이미 요청한 기능이다.

| # | 질문 | 왜 지금인가 |
|---|---|---|
| 1 | 참여자 문장을 서비스가 쓸 근거를 어떻게 확보할 것인가 | 공유 기능의 전제 |
| 2 | 완성본에 기여자를 어떻게 표시할 것인가 | *"내 것"* 감각과 직결 |
| 3 | 외부 공유 시 **AI 생성물임을 표시**할 것인가 | 선행 연구에서 디자인 실무자들이 **명시를 필수 조건**으로 꼽았다 |
| 4 | 탈락한 문장도 남길 것인가 | 남기면 그것도 권리 대상이 된다 |

3번은 특히 분명하다. 선행 연구에서 디자인 관계자 집단은
**"AI를 활용했다"는 표기가 저작권 부여의 필수 조건**이라고 주장했다.
공유 기능을 만든다면 **AI 생성 표시를 기본값으로** 두는 것이 안전하다.

---

## 5. 조사·실험에서의 윤리

저작권과 별개로, 사용자 조사에 따라오는 문제다.

| 항목 | 현재 상태 |
|---|---|
| 참여자 문장 수집 | 고지 없음 |
| 닉네임 수집 | 화면에 표시되나 별도 안내 없음 |
| 인터뷰 녹음 | [가이드](../Research/비교%20인터뷰%20가이드.md)에 동의 문구 있음 |
| 행동 로깅 | 미구현. 구현 시 고지 필요 |
| 미성년 참여 | 처리 방침 없음 |
| 데이터 보관·폐기 | 정해진 바 없음 |

**연구 결과를 외부에 발표한다면** 참여자 발언 인용에 대한 동의가 별도로 필요하다.

## 6. 서비스화한다면

| 항목 | 검토할 것 |
|---|---|
| 이용약관 | 입력 문장의 이용 범위, 결과물 권리 귀속 |
| CP사 계약 | 2차적저작물작성권 확인 (3.4) |
| AI 생성 표시 | 결과물과 공유물에 일관 적용 |
| 스타일 레퍼런스 | 작품명 직접 지목 재검토 (3.6) |
| 상업적 이용 | 저작물이 아닌 결과물을 상품화할 수 있는가 |
| 분쟁 대응 | 생성물이 기존 작품과 유사할 경우의 절차 |

> *JCCT*, 9(1), 777-786. DOI: 10.17703/JCCT.2023.9.1.777

이 연구에서 확인된 것 중 우리에게 직접 걸리는 것:

| 발견 | 우리 적용 |
|---|---|
| 활용 의도가 높을수록 저작권을 강하게 주장했다 | 공유 기능을 붙이면 권리 주장도 함께 올라온다 |
| 만족도·관여도는 저작권 주장에 영향이 적었다 | 잘 만들어졌다고 내 것이라 느끼는 것은 아니다 |
| 디자인 실무자는 **AI 사용 명시를 필수 조건**으로 봤다 | 표시를 기본값으로 |
| 일반인은 긍정적, 디자인 관계자는 부정적 | 참여자 직군에 따라 반응이 갈릴 수 있다 |
