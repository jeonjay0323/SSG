# 멀티툴 로그 관찰

합본 시안(`/solo`)에 화면 트래킹을 붙이고 처음 모은 기록이다.
무엇이 눌렸는지만 남기고 문장 내용은 보내지 않는다 — 문장은 이미 서버에 있다.

    화면 ──POST /api/track──▶ events.jsonl ──GET /api/events──▶ 분석

## 무엇을 남기나

| 이벤트 | 언제 | 같이 남는 것 |
|---|---|---|
| `screen` | 화면이 바뀔 때 | 화면 id |
| `tab` · `seg` | 하단 탭 · 오리지널/창작 전환 | 이름 |
| `open_story` | 스토리에 들어갈 때 | 스토리 id, 어디서 눌렀는지 |
| `cta_write` | 상세에서 쓰기로 갈 때 | 스토리 id |
| `submit_ok` | 문장이 접수됐을 때 | 길이, 대사 여부, 코인 사용 여부 |
| `submit_blocked` | 막혔을 때 | 화면이 막았는지 서버가 막았는지 |
| `hint` | 제안 문장·키워드를 눌렀을 때 | 종류 |
| `vote` | 후보를 골랐을 때 | 스토리 id |
| `share_open` · `share_done` | 공유를 열고 보냈을 때 | 홈인지 상세인지 |
| `reward_pick` | 첫 문장 보상을 골랐을 때 | 고른 값 |
| `coin_use` · `coin_buy_tap` | 코인을 쓰거나 충전을 눌렀을 때 | 남은 개수 |
| `random_popup` · `random_spin` | 고르지 못한 사람에게 뜬 팝업과 슬롯 | 뽑힌 스토리 |
| `viewer_open` | 전체 화면으로 볼 때 | 스토리 id |

## 첫 관찰 — 실제 사용 기록

기기 4대, 121건.

| 기능 | 건수 |
|---|---|
| 화면 전환 | 60 (갤러리 27 · 상세 15 · 쓰기 6 · 참여한 스토리 6) |
| 스토리 열기 | 15 (전부 카드에서) |
| 쓰기 진입 | 6 |
| 문장 보내기 | 5 (16~39자, 대사 1건) |
| 전체 화면 | 3 |
| 보상 선택 | 5 (클립 저장 2 · 후보 올리기 2 · 비밀방 1) |
| 랜덤 팝업 | 5 (슬롯을 돌린 사람 0) |
| 힌트 | 1 |
| 공유 · 코인 · 차단 | 0 |

### 읽히는 것

**깔때기가 상세에서 좁아진다.** 갤러리 27 → 상세 15 → 쓰기 6.
카드를 눌러 들어오긴 하는데 거기서 쓰기로 넘어가는 비율이 40%다.
상세가 '읽고 나오는 화면'이 되고 있다.

**들어가면 거의 다 쓴다.** 쓰기 화면 6회 중 5건이 접수됐다.
문턱은 쓰는 일 자체가 아니라 그 앞의 결심에 있다.

**대사를 쓴 사람이 다섯 중 하나.** 안내가 플레이스홀더 한 줄뿐인 것치고는 높다.

**고르기를 도와주겠다는 제안이 통하지 않았다.** 30초 팝업이 다섯 번 떴는데
아무도 슬롯을 돌리지 않았다. 고민 중이라 안 누른 것인지 방해로 느낀 것인지는
로그만으로 알 수 없다 — 인터뷰가 필요하다.

**공유와 코인은 존재를 모른다.** 상단 공유 버튼은 한 번도 눌리지 않았고,
텀이 30초라 코인을 쓸 이유가 없었다. 코인은 텀이 길 때만 의미가 생긴다.

## 기능 점검 — 개발자 테스트 세션

위 관찰에서 한 번도 찍히지 않은 경로가 실제로 도는지 직접 눌러 확인했다.
관람 기록이 아니라 점검 기록이다. 드라이런 서버에서 돌려 생성 비용은 들지 않았다.

| 경로 | 결과 |
|---|---|
| 공유(홈) → 팝업 | `share_open {"where":"home"}` |
| 공유(상세) → 초대 | `share_open {"where":"detail","sid":"isekai"}` |
| 전체 화면 | `viewer_open` |
| 대사 문장 보내기 | `submit_ok {"len":18,"dialogue":true}` |
| 첫 문장 보상 | `reward_pick {"pick":"room"}` |
| 랜덤 슬롯 | `random_spin {"sid":"isekai"}` |
| 코인 충전 탭 | `coin_buy_tap` |
| 코인 사용 | `coin_use {"left":2}` |
| 링크 차단 | `submit_blocked {"by":"client"}` |

`share_done` 만 찍히지 않았다. 데스크톱에서는 `navigator.share` 가 없어 클립보드로
떨어지는데, 창이 포커스를 잃으면 브라우저가 클립보드 쓰기를 막는다(`NotAllowedError`).
폰에서는 공유 시트가 떠서 이 경로를 타지 않는다.

## 고칠 것

- **`reward_pick` 의 `sid` 가 `null`** — 보상 팝업이 뜰 때는 이미 홈으로 나온 뒤라
  어느 스토리에서 받은 보상인지 남지 않는다.
- **진입 경로가 한 가지로만 보인다** — `open_story` 가 전부 `from: card` 다.
  알림·참여한 스토리에서 들어온 경우도 구분해 남겨야 한다.
- **공유 실패가 기록되지 않는다** — 클립보드가 막히면 조용히 끝난다.
