# 슥 · 멀티툴

참여형 창작물. 참여자가 폰으로 **한 문장**을 보내면 그 문장이 영상 장면이 되고,
장면들이 이어져 하나의 웹드라마가 된다.

```
폰 /write ──▶ 문장 접수 ──▶ [동시 참여면 투표] ──▶ 영상 생성 ──▶ 대형화면 /stage
                                                        └── 다음 씬의 시작 프레임으로 체이닝
```

화면은 두 갈래다. 큰 화면이 따로 있는 자리에서는 `/write` + `/stage` 를 쓰고,
폰 하나로 끝내는 자리에서는 둘을 합친 **`/solo`** 를 쓴다.

## 흐름

1. **이야기 고르기** — 시나리오 3개 중 하나를 고르면 그 도입부가 재생된다
   (이세계 용사 · 애니 / 야근 · 실사 / 게이트 · 웹툰 — 각각 다른 배우와 톤)
2. **이름 정하기** — 큰 화면 자막에 문장과 함께 뜰 이름을 정한다 (건너뛸 수 있다)
3. **한 문장** — 참여자가 다음에 일어날 일을 한 문장으로 쓴다
4. **투표** — 접수 창(20초, 새 문장마다 연장) 안에 2명 이상이 참여하면
   후보 영상 중 하나를 투표로 고른다
5. **편입** — 당선작이 정사(canon)가 되고, 그 마지막 프레임에서 다음 씬이 이어진다
6. 6씬이 차면 이야기가 끝나고 다시 선택 화면으로 돌아간다

세 이야기는 **동시에, 서로 독립적으로** 돈다. 한 이야기가 투표 중이어도 다른 이야기는
접수를 받는다. 대형 화면은 9:16 세 칸으로 나뉘어 셋을 함께 보여준다.

한 번 쓰면 그 이야기에는 **30초 동안 다시 쓸 수 없다**(`round.cooldownSeconds`).
한 사람이 이야기를 끌고 가지 않게 하려는 장치이고, 코인으로 건너뛸 수 있다.
문장은 5~40자, 따옴표로 쓴 부분은 **인물의 대사**가 되어 목소리로 생성된다.

## 구성

```
App/         서버 — Dockerfile 이 실행하는 것
Tools/       CLI — 세계 만들기 · 레퍼런스 생성 · 얼굴 교정
Templates/   write.html  stage.html  write_stage.html
Config/      story.json  scenarios/  worlds/
Static/      scenes/ — 도입부 스틸 · 인물 레퍼런스
```

| 파일 | 역할 |
|---|---|
| `App/server.py` | 라운드 상태머신 · 투표 · 입력 필터 · 예산 캡 (Python 표준 라이브러리만) |
| `App/restage.py` | **핵심** — 다음 컷의 시작 프레임을 다시 세운다 (얼굴 교정 + 샷 문법) |
| `App/generate_clip.py` | 시작 프레임 → Veo 3.1 영상 |
| `App/beat.py` | 참여자 문장 → 촬영 가능한 장면 묘사 (글자 렌더 차단 · 세계 접지) |
| `App/frames.py` | 프레임 추출 · 클립 트림 (체이닝 이음매 맞추기) |
| `App/transcribe.py` | 클립에서 들리는 말을 받아 적는다 (자막의 출처) |
| `App/storage.py` | 로컬 / GCS 양쪽 지원 · 이벤트 로그 적립 |
| `Templates/write.html` | 폰 화면 — 선택 · 입력 · 투표 |
| `Templates/stage.html` | 대형 화면 — 상영 · 실시간 득표 |
| `Templates/write_stage.html` | 합본(`/solo`) — 상영창을 폰 안에 들인 한 화면 |
| `Config/story.json` | 공통 설정 — 라운드 타이밍, 시나리오 목록 |
| `Config/scenarios/*.json` | **이야기** — 제목 · 로그라인 · 첫 문장 · 도입 씬 |
| `Config/worlds/*.json` | **연출** — 배우 · 의상 · 색감 · 감독 레이어 · 샷 6종 · 네거티브 |

`python3 Tools/build_world.py <world> refs|intro` 로 새 세계의 배우 레퍼런스와 도입 이미지를 만든다.
프롬프트는 전부 `Config/worlds/<id>.json` 에서 읽으므로 코드를 고칠 필요가 없다.

**코드에 프롬프트가 없다.** 톤·샷·배우를 바꾸려면 JSON 만 고치면 된다.

## 합본 화면 (`/solo`)

큰 화면 없이 폰 하나로 도는 구성. 상영창을 위에 두고 그 아래에서 쓴다.

| 화면 | 하는 일 |
|---|---|
| 갤러리 | 9:16 포스터 카드. 마지막 장면이 돌고, 배지로 상태를 읽는다 (선점하기 / 진행중 / 완결) |
| 스토리 상세 | 상영창 · 지금까지 쓰인 문장 · 투표 · 하단 고정 버튼 |
| 쓰기 | 앞 문장과 입력칸을 한 줄기로. 키보드가 올라오면 보내기 버튼이 따라 올라온다 |
| 알림 | 내가 참여한 스토리에서 투표가 열리거나, 내 문장이 이어지거나, 완결됐을 때 |
| 참여한 스토리 | 스토리가 아니라 **내가 쓴 문장**을 모아 보여준다 |

- **투표는 상세 안에서** 한다. 후보를 비교하려면 화면이 넓어야 하고, 알림 → 상세 → 투표가 한 줄기가 된다.
- **첫 문장 보상** — 아무도 쓰지 않은 스토리를 연 사람에게 셋 중 하나를 고르게 한다
  (비밀방 생성 · 후보로 올리기 · 클립 저장). 무엇을 고르는지가 곧 관찰 자료다.
- **30초 동안 고르지 못하면** 슬롯으로 하나 골라주겠다고 묻는다. 누르기 전에는 아무것도 진행되지 않는다.
- 디자인 토큰은 원티드 디자인 시스템(Dark)을 따르고, 아이콘은 Heroicons 를 인라인으로 넣는다.

## 대사와 자막

**영상에는 글자가 없다.** 프롬프트에서 글자 렌더를 막아두었기 때문에, 자막은 화면에서 겹쳐 그린다.

- 따옴표로 쓴 문장은 `beat.spoken` 이 대사로 떼어내고, 프롬프트에 대사 블록이 붙으면서 Veo 오디오가 켜진다.
- 자막은 쓴 문장이 아니라 **들리는 말**이다. `transcribe.heard` 가 클립의 오디오를 받아 적어 대사를 갈아끼운다.
  말이 없으면 자막도 없다. 틀린 자막보다 없는 편이 낫다.
- `SSG_AUDIO=0` 이면 오디오 생성과 받아쓰기를 모두 건너뛴다.

## 트래킹

무엇이 눌렸는지만 남긴다. **문장 내용은 보내지 않는다** — 서버에 이미 있다.

```
화면 ──POST /api/track──▶ events.jsonl ──GET /api/events──▶ 분석
```

화면 전환 · 탭 · 스토리 진입 · 보내기 결과 · 힌트 · 투표 · 공유 · 보상 · 코인 · 랜덤 · 전체 화면을 남긴다.
모았다가 `sendBeacon` 으로 흘려보내고, 버킷이 있으면 `events.jsonl` 로 같이 올라간다.
읽는 법과 첫 관찰은 [멀티툴 로그 관찰](../../02_Docs/Research/멀티툴%20로그%20관찰.md) 에 있다.

## 설계 메모

작업하며 실측으로 확인한 것들. 다시 만들 때 같은 함정을 피하려고 남긴다.

**Veo 3.1 은 시작 프레임과 인물 레퍼런스를 함께 못 받는다**
`Image and reference images cannot be both set`. 게다가 reference-to-video 는
standard 티어 + 8초에서만 동작한다. 그래서 인물 고정은 Veo 가 아니라
**이미지 모델 단계**(`restage.py`)에서 한다 — Veo 에 넘기기 전에 얼굴을 레퍼런스로
되돌린 프레임을 만들어 넣는다.

**얼굴 교정과 앵글 변경은 다른 주기로 돈다**
둘을 한 스위치로 묶으면 앵글을 유지하는 씬에 레퍼런스가 아예 안 들어가서 얼굴이
세대마다 밀린다. 교정은 매 씬, 앵글은 `restageEvery` 주기로.

**체이닝은 클립을 잘라야 성립한다**
화이트아웃 등으로 시드 프레임을 앞 시점에서 뽑으면, 클립은 끝까지 재생되는데 다음 씬은
그 앞 상태에서 시작해 되감기처럼 보인다. `frames.trim()` 으로 시드 지점에서 잘라
**클립의 끝 = 다음 씬의 시작**을 맞춘다.

**대기 시간은 선행 처리로 숨긴다**
접수 마감을 기다렸다 리스테이징하면 그 시간이 그대로 대기가 된다. 제출 즉시
백그라운드로 시작하면 접수 창 안에 숨는다. 제출→완성 72초 → **47초**.

**연출은 참여자에게 보이지 않는 층에서 정한다**
참여자는 "무슨 일이 일어나는가"만 쓰고, "어떻게 찍는가"는 전부 감독 레이어가 정한다.
세계마다 매체가 다르다 — 애니메이션 / 실사 / 웹툰. 어느 세계든 인물은 카메라를 보지 않는다.

**참여자 문장을 그대로 Veo 에 넘기면 글자가 찍힌다**
"안녕" 처럼 그릴 게 없는 입력이 오면 모델은 그 단어를 자막이나 간판으로 그려 넣는다.
세계 밖 소재("지하철이 왔다")도 그대로 렌더된다. `beat.py` 가 앞단에서 문장을 세계 안의
**찍을 수 있는 사건**으로 바꾼다. 자막에는 원문을 그대로 띄워 소유감은 지킨다.

**이야기 셋을 동시에 굴린다**
트랙이 하나면 앞사람 라운드가 끝날 때까지 아무도 참여할 수 없다. 트랙을 셋으로 분리해
각자 독립된 라운드를 돌린다. 락 순서(**트랙 먼저, 공유 카운터 나중**)를 지키지 않으면
세 트랙이 동시에 끝나는 순간 데드락으로 서버가 멈춘다.

**클라이언트가 story 를 한 번만 읽으면 안 된다**
배포해도 열려 있던 화면이 옛 시나리오를 계속 보여준다. 15초마다 다시 읽고,
목록이 바뀌면 카드를 다시 그린다.

**대기 시간은 볼거리로 바꾼다**
접수 중에는 들어온 문장이 큰 화면에 쌓이고(보낸 사람이 확인할 수 있다),
생성 중에는 리스테이징된 첫 프레임을 먼저 크게 보여준다 — 빈 34초가 사라진다.

## 실행

```bash
pip install -r 01_Product/MultiTool/requirements.txt

cd 01_Product/MultiTool
python3 App/server.py                          # 드라이런 (생성 호출 없음, 무료)
python3 App/server.py --live --budget 15       # 실제 생성 · 누적 $15 에서 자동 드라이런 전환
python3 App/server.py --live --fast            # 라운드를 짧게 (테스트용)
```

`http://localhost:8778/solo` · `http://localhost:8778/write` · `http://localhost:8778/stage`

### 배포 (Cloud Run)

라운드 드라이버가 백그라운드 스레드로 돌기 때문에 **CPU 상시 할당이 필요**하고,
라운드 상태가 메모리에 있으므로 **인스턴스는 정확히 1개**여야 한다.

```bash
# 저장소 루트에서 실행한다
gcloud run deploy ssg-theater --source 01_Product/MultiTool --region us-central1 \
  --allow-unauthenticated --no-cpu-throttling \
  --min-instances 1 --max-instances 1 --memory 2Gi --cpu 2 --timeout 3600 \
  --set-env-vars "SSG_LIVE=1,SSG_BUDGET=15,SSG_BUCKET=<버킷>,GOOGLE_CLOUD_PROJECT=<프로젝트>"
```

| 환경변수 | 뜻 |
|---|---|
| `SSG_BUCKET` | 생성 클립·스냅샷을 둘 GCS 버킷. 없으면 로컬 파일 |
| `SSG_LIVE` | `1` 이면 실제 생성 |
| `SSG_BUDGET` | 누적 생성비 상한(USD). 도달하면 조용히 드라이런으로 내려간다 |
| `SSG_MAX` | 최대 생성 건수 |
| `SSG_AUDIO` | `0` 이면 오디오 생성과 자막 받아쓰기를 끈다 (기본 켬) |

## 자산

`Static/scenes/` 의 이미지만 저장소에 있다. 영상(mp4)은 용량이 커서 제외했고 GCS 에 둔다.
`story.json` 이 가리키는 `/clips/*.mp4` 를 버킷의 `clips/` 에 올려두면 된다.
