# 슥 · 한 줄 극장

졸업전시 부스 설치물. 관람객이 폰으로 **한 문장**을 보내면 그 문장이 영상 장면이 되고,
장면들이 이어져 하나의 웹드라마가 된다.

```
폰 /write ──▶ 문장 접수 ──▶ [동시 참여면 투표] ──▶ 영상 생성 ──▶ 대형화면 /stage
                                                        └── 다음 씬의 시작 프레임으로 체이닝
```

## 흐름

1. **이야기 고르기** — 시나리오 3개 중 하나를 고르면 그 도입부가 재생된다
   (이세계 용사 · 애니 / 야근 · 실사 / 게이트 · 웹툰 — 각각 다른 배우와 톤)
2. **한 문장** — 관람객이 다음에 일어날 일을 한 문장으로 쓴다
3. **투표** — 접수 창(15초) 안에 2명 이상이 참여하면 후보 영상들 중 하나를 투표로 고른다
4. **편입** — 당선작이 정사(canon)가 되고, 그 마지막 프레임에서 다음 씬이 이어진다
5. 6씬이 차면 이야기가 끝나고 다시 선택 화면으로 돌아간다

## 구성

| 파일 | 역할 |
|---|---|
| `server.py` | 라운드 상태머신 · 투표 · 입력 필터 · 예산 캡 (Python 표준 라이브러리만) |
| `restage.py` | **핵심** — 다음 컷의 시작 프레임을 다시 세운다 (얼굴 교정 + 샷 문법) |
| `generate_clip.py` | 시작 프레임 → Veo 3.1 영상 |
| `frames.py` | 프레임 추출 · 클립 트림 (체이닝 이음매 맞추기) |
| `storage.py` | 로컬 / GCS 양쪽 지원 |
| `write.html` | 폰 화면 — 선택 · 입력 · 투표 |
| `stage.html` | 대형 화면 — 상영 · 실시간 득표 |
| `story.json` | 공통 설정 — 라운드 타이밍, 시나리오 목록 |
| `scenarios/*.json` | **이야기** — 제목 · 로그라인 · 첫 문장 · 도입 씬 |
| `worlds/*.json` | **연출** — 배우 · 의상 · 색감 · 감독 레이어 · 샷 6종 · 네거티브 |

`build_world.py <world> refs|intro` 로 새 세계의 배우 레퍼런스와 도입 이미지를 만든다.
프롬프트는 전부 `worlds/<id>.json` 에서 읽으므로 코드를 고칠 필요가 없다.

**코드에 프롬프트가 없다.** 톤·샷·배우를 바꾸려면 JSON 만 고치면 된다.

## 설계 메모

작업하며 실측으로 확인한 것들. 다시 만들 때 같은 함정을 피하려고 남긴다.

**Veo 3.1 은 시작 프레임과 인물 레퍼런스를 함께 못 받는다**
`Image and reference images cannot be both set`. 게다가 reference-to-video 는
standard 티어 + 8초에서만 동작한다. 그래서 인물 고정은 Veo 가 아니라
**이미지 모델 단계**(`restage.py`)에서 한다 — Veo 에 넘기기 전에 얼굴을 레퍼런스로
되돌린 프레임을 만들어 넣는다.

**얼굴 교정과 앵글 변경은 다른 주기로 돈다**
둘을 한 스위치로 묶으면 앵글을 유지하는 씬에 레퍼런스가 아예 안 들어가서 얼굴이
세대마다 밀린다. 교정은 매 씬, 앵글은 `restageEvery` 주기로.

**체이닝은 클립을 잘라야 성립한다**
화이트아웃 등으로 시드 프레임을 앞 시점에서 뽑으면, 클립은 끝까지 재생되는데 다음 씬은
그 앞 상태에서 시작해 되감기처럼 보인다. `frames.trim()` 으로 시드 지점에서 잘라
**클립의 끝 = 다음 씬의 시작**을 맞춘다.

**대기 시간은 선행 처리로 숨긴다**
접수 마감을 기다렸다 리스테이징하면 그 시간이 그대로 대기가 된다. 제출 즉시
백그라운드로 시작하면 접수 창 안에 숨는다. 제출→완성 72초 → **47초**.

**연출은 관람객에게 보이지 않는 층에서 정한다**
관람객은 "무슨 일이 일어나는가"만 쓰고, "어떻게 찍는가"는 전부 감독 레이어가 정한다.
세계마다 매체가 다르다 — 애니메이션 / 실사 / 웹툰. 어느 세계든 인물은 카메라를 보지 않는다.

**클라이언트가 story 를 한 번만 읽으면 안 된다**
배포해도 열려 있던 화면이 옛 시나리오를 계속 보여준다. 15초마다 다시 읽고,
목록이 바뀌면 카드를 다시 그린다.

**대기 시간은 볼거리로 바꾼다**
접수 중에는 들어온 문장이 큰 화면에 쌓이고(보낸 사람이 확인할 수 있다),
생성 중에는 리스테이징된 첫 프레임을 먼저 크게 보여준다 — 빈 34초가 사라진다.

## 실행

```bash
pip install -r requirements.txt

python3 server.py                          # 드라이런 (생성 호출 없음, 무료)
python3 server.py --live --budget 15       # 실제 생성 · 누적 $15 에서 자동 드라이런 전환
python3 server.py --live --fast            # 라운드를 짧게 (테스트용)
```

`http://localhost:8778/write` · `http://localhost:8778/stage`

### 배포 (Cloud Run)

라운드 드라이버가 백그라운드 스레드로 돌기 때문에 **CPU 상시 할당이 필요**하고,
라운드 상태가 메모리에 있으므로 **인스턴스는 정확히 1개**여야 한다.

```bash
gcloud run deploy ssg-theater --source . --region us-central1 \
  --allow-unauthenticated --no-cpu-throttling \
  --min-instances 1 --max-instances 1 --memory 2Gi --cpu 2 --timeout 3600 \
  --set-env-vars "SSG_LIVE=1,SSG_BUDGET=15,SSG_BUCKET=<버킷>,GOOGLE_CLOUD_PROJECT=<프로젝트>"
```

| 환경변수 | 뜻 |
|---|---|
| `SSG_BUCKET` | 생성 클립·스냅샷을 둘 GCS 버킷. 없으면 로컬 파일 |
| `SSG_LIVE` | `1` 이면 실제 생성 |
| `SSG_BUDGET` | 누적 생성비 상한(USD). 도달하면 조용히 드라이런으로 내려간다 |
| `SSG_MAX` | 최대 생성 건수 |

## 안전장치

전시는 무인으로 며칠을 버텨야 하므로, 실패해도 부스가 죽지 않게 만들었다.

- **입력 필터** — 접수 시점에 차단. 자모 분리·기호 삽입 우회까지 정규화해서 잡는다
- **canon 스냅샷** — 라운드 확정마다 저장. 서버가 죽어도 이야기가 이어진다
- **예산 캡** — 건수·금액 양쪽. 넘으면 드라이런으로 전환되고 정지화면으로 계속 돌아간다
- **리스테이징 실패** — 원본 체인 프레임으로 폴백
- **생성 실패** — 정지화면으로 강등하고 투표는 그대로 진행

## 자산

`scenes/` 의 이미지만 저장소에 있다. 영상(mp4)은 용량이 커서 제외했고 GCS 에 둔다.
`story.json` 이 가리키는 `/clips/*.mp4` 를 버킷의 `clips/` 에 올려두면 된다.
